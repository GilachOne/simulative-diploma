# Диплом: требования и принятые решения

Задание: https://app.simulative.ru/course/14/1263

## Обязательные части

1. Получение данных маркетплейса из API.
2. PostgreSQL на сервере.
3. Ежедневная загрузка предыдущего дня в 07:00.
4. Первичная загрузка всей доступной истории.
5. Metabase: продажи, активность клиентов, ассортимент и качество загрузки.
6. Два исследования по 2023 году: ассортимент и клиентская база/LTV. Нужны код, графики и конкретные рекомендации.
7. Для сдачи: публичный GitHub, адрес сервера и доступы (передаются отдельно), доступ к Metabase, два документа или презентации.

## Наблюдения API, 21 сентября 2026

- Адрес: `http://final-project.simulative.ru/data?date=YYYY-MM-DD`.
- Успешный ответ — JSON-массив, несмотря на Content-Type text/html.
- Сообщения об ошибках могут возвращаться со статусом HTTP 200.
- Первые доступные данные: 2022-01-01. Проверен переход между 2021-12-31 и 2022-01-01, граница найдена бинарным поиском.
- API отдаёт даже будущие даты. В проекте они запрещены: исторический срез ограничен вчерашним календарным днём. Это учебный генератор, а не подтверждение реальных будущих продаж.
- Повторные ответы одного дня могут менять порядок строк. На проверенном дне состав и кратность строк совпали. Хеш снимка рассчитывается после сортировки канонических строк.
- При параллельных запросах обнаружены смешанные даты и частично заполненные ответы. Последовательная повторная проверка 2023-01-03 и 2023-08-04 вернула корректные даты и другой состав строк. Диагностическая параллельная загрузка изолирована и не используется в исследованиях. Рабочая загрузка выполняется строго последовательно; общий advisory lock PostgreSQL предотвращает одновременные запросы даже из разных экземпляров скрипта. Ответ с несовпадающими/отсутствующими датами целиком повторяется, а не принимается за неполный день.
- Нет ID заказа, названий и категорий товаров, себестоимости, расходов привлечения. Нельзя корректно считать средний чек заказа, прибыль и маржинальный lifetime LTV.
- Есть нулевые количества, пропуски дат, несовпадения даты строки с запрошенным днём, некорректное время. Их нельзя незаметно исправлять: исходные данные сохраняются, строки отправляются в карантин с причиной. В анализе обязательно показывается размер исключений.

## Локальный этап

Пользователь выбрал сначала подготовку локально, без аренды сервера. База `marketplace_diploma` отделена от других учебных проектов. Секреты не входят в репозиторий. Время ежедневного запуска — Europe/Moscow, выбранное явно; API не документирует собственный часовой пояс.

Отсутствие ошибок запуска не означает готовность диплома к сдаче: необходимы проверка полноты истории, два завершённых исследования, работающий Metabase и затем размещение на доступном преподавателю сервере.
