# Диплом Simulative: аналитика маркетплейса

Задание: https://app.simulative.ru/course/14/1263

**Статус: локальная подготовка.** Удалённый сервер ещё не выбран. Полнота загрузки и готовность исследований должны быть проверены перед сдачей.

## Архитектура

API → сохранённый снимок дня → проверка данных → PostgreSQL → Metabase и два исследования в Python.

- `etl.py` — последовательная загрузка, повторы при сбоях, снимки и защита от повторной вставки.
- `sql/schema.sql` — таблицы и представления для дашборда.
- `run_local.py` — запуск на текущем Windows-компьютере с приватными настройками.
- `export_research.py` — агрегаты для двух исследований, экспорт только после загрузки всех 365 дней 2023 года.
- `build_reports.py`, `run_reports.py` — сборка и выполнение двух Jupyter Notebook и HTML-отчётов.
- `metabase_setup.py` — создание дашборда через API Metabase.
- `tests/` — проверки преобразований.
- `deploy/` — ежедневное расписание Windows и инструкции/systemd для будущего Linux VPS.
- `BRIEF.md` — требования и наблюдения о нестандартном поведении API.

## Запуск

Нужны Python 3.12+, PostgreSQL, переменные `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`, `PGPASSWORD` (или pgpass). Создайте отдельную базу `marketplace_diploma`. Пароль в Git не хранится.

```bash
python -m pip install -r requirements.txt
python etl.py --start 2022-01-01
python etl.py --daily
python -m unittest discover -s tests -v
```

Параметр `--end YYYY-MM-DD` включителен. Без него конец — вчера. `--daily` загружает только вчерашний день. Часовой пояс явно задаётся `BUSINESS_TIMEZONE`, по умолчанию Europe/Moscow.

API нельзя загружать параллельно: при проверке обнаружено смешивание дат. Общая блокировка PostgreSQL сериализует запросы нескольких экземпляров. Для защиты от дублей используется журнал `etl_days`, а не предположение, что каждая комбинация полей уникальна. Полностью одинаковые строки в одном снимке сохраняются с номером вхождения: у источника нет ID заказа/строки, поэтому нельзя безусловно считать совпадение полей дублем.

Строки принятого дня и запись о его загрузке фиксируются одной транзакцией. При ошибке вставки всё откатывается. Уже записанный исходный снимок остаётся для повторного запуска. Снимки сортируются только для контрольной суммы; порядок выдачи API может изменяться.

## Исследования

После полной загрузки 2023 года:

```bash
python export_research.py
python build_reports.py
python run_reports.py
```

В `reports/` появятся два выполненных ноутбука и два HTML-документа с кодом, графиками и выводами: ассортимент и клиенты. Исходные снимки, клиентские списки, журналы и приватные конфиги находятся в `data/` и исключены из Git. Публичные результаты должны содержать агрегаты, а не доступы.

## Метрики

Выручка — сумма после скидок; активные клиенты и SKU — distinct ID за период. Количество товарных строк не называется числом заказов. В API нет валюты, себестоимости, ID заказа и названий товаров. Годовая выручка на клиента не выдаётся за lifetime LTV, скидка — за маржу, сценарий кампании — за измеренный эффект.

Локальный Metabase: http://127.0.0.1:3030/dashboard/2 (только на компьютере проекта, нужен вход).

## Что требуется для окончательной сдачи

Проверенная история с 2022-01-01 до вчерашнего дня, два завершённых исследования, GitHub со скриптами, доступный преподавателю сервер и Metabase. Локальная установка не заменяет этот сервер. Доступы передаются отдельно.
