# Перенос на VPS

Развёрнуто на Ubuntu 26.04.1, 2 vCPU, 4 ГБ RAM, 48 ГБ диска. PostgreSQL 18 и Metabase 0.63.18 работают как службы. Ниже описано воспроизведение настройки. Текущий статус полноты истории указан в основном README.

## Конфигурация

Для этого набора используются 2 vCPU, 4 ГБ RAM и внешний IPv4. Для базы, сырых архивов и резервных копий нужен запас диска. На ARM устанавливается соответствующая ARM-сборка Java; JAR Metabase переносим между архитектурами.

Локально используются PostgreSQL 16, Metabase 0.63.18 и Java 25.0.4.1. Актуальный Metabase требует Java 25: https://www.metabase.com/docs/latest/installation-and-operation/running-the-metabase-jar-file

## Порядок переноса

1. Установить PostgreSQL, Python 3 с venv и Java 25 из официальных источников. Установить актуальные исправления безопасности выбранной ветки PostgreSQL.
2. Создать системных пользователей `diploma` и `metabase`, каталоги `/opt/simulative-diploma` и `/opt/metabase`. Разместить код и официальный Metabase JAR.
3. В PostgreSQL создать базу `marketplace_diploma` и пользователя `diploma_loader` с правами на собственную схему. Создать отдельную служебную базу `diploma_metabase` и её пользователя. Для подключения аналитических данных в Metabase использовать отдельного `diploma_reader` только с SELECT.
4. Создать venv проекта и установить `requirements.txt`. Скопировать `environment.example` в `/etc/simulative-diploma.env`, указать локальные серверные реквизиты. Файл должен читаться только root и пользователем службы; не добавлять его в GitHub.
5. Восстановить проверенную локальную БД из резервной копии, если она есть, затем заполнить недостающую историю последовательной загрузкой (уже записанные даты пропускаются):

   ```bash
   /opt/simulative-diploma/.venv/bin/python etl.py --init-schema
   /opt/simulative-diploma/.venv/bin/python etl.py --start 2022-01-01
   ```

   Конец по умолчанию — вчерашний день по Europe/Moscow. Не задавать будущие даты: учебный API умеет их генерировать, но это не исторические продажи. Повторный запуск пропускает уже загруженные дни. При сбоях повторить тот же диапазон и сверить полноту в `etl_days`.
6. Скопировать `diploma-etl.service` и `.timer` в `/etc/systemd/system/`; выполнить `systemctl daemon-reload`, затем `systemctl enable --now diploma-etl.timer`. Проверить `systemctl list-timers diploma-etl.timer`. Таймер использует 07:00 Europe/Moscow. `Persistent=true` обеспечивает запуск после простоя, но не заполняет автоматически все пропущенные за длительный простой даты: для них повторить диапазон загрузки.
7. Скопировать `metabase.env.example` в `/etc/metabase.env`, заполнить пароль отдельной служебной базы. Установить `metabase.service`, запустить и проверить `/api/health`.
8. Перенести служебную БД Metabase либо пересоздать дашборд через `metabase_setup.py` с адаптированным приватным конфигом. При переносе изменить порт аналитической базы с локального 55440 на серверный 5432. Дашборд должен подключаться пользователем `diploma_reader`.
9. Доступ преподавателю к Metabase — через SSH-туннель или HTTPS reverse proxy. PostgreSQL оставить на localhost; преподаватель подключается через SSH-туннель. Проверить вход с другой машины до сдачи. Публичный GitHub не должен содержать пароли, сессии или дампы служебной базы.
10. Отдельно передать преподавателю адрес сервера, ограниченный SSH-доступ, доступ только для чтения к аналитической базе и аккаунт Metabase. Проверить ожидания преподавателя по способу подключения. Пароли не писать в README.

## Резервные копии и контроль

Резервировать обе PostgreSQL-базы: аналитическую и служебную Metabase (в ней хранятся дашборды). `pg_dump` должен быть той же или более новой основной версии, чем сервер. После восстановления проверить число дней, строк и контрольные суммы снимков. Бэкапы содержат приватные настройки и не включаются в публичный репозиторий.

После ежедневного запуска проверить код выхода, запись за вчера в `etl_days` и журнал. Карантин не должен незаметно превращаться в падение бизнеса: его доля выведена на дашборд.
